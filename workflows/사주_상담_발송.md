# Workflow: 사주 상담 판매 · 풀이 발송

## 목표
손님 신청 → 입금 확인 → 풀이 작성·수정 → PDF를 손님 이메일로 발송. 사장님 혼자 하루 몇 건씩 처리할 수 있게.

## 필요한 입력
- 손님 신청 (사이트 첫 화면 신청서, 또는 카톡·DM으로 받은 정보)
- 사장님 통장 입금 내역 (입금자명 = 신청자 이름)

## 사용할 Tool (모두 `saju/` 서버 안)
- 신청서: `saju/static/apply.html` (주소 `/`, 채널 추적 `/?src=threads`)
- 관리 화면: `saju/static/admin.html` (주소 `/admin`, `ADMIN_EMAIL` 계정만)
- 신청 저장: `saju/orders.py` / 풀이: `saju/interpret.py` / PDF: `saju/pdf_report.py` / 메일: `saju/mailer.py`

## 설정 (saju/.env, 처음 한 번)
| 이름 | 뜻 | 예 |
|---|---|---|
| `ADMIN_EMAIL` | 사장님 로그인 이메일. 이 계정만 관리 화면·가입 가능 | eager1014@gmail.com |
| `BANK_ACCOUNT` | 손님에게 보여줄 입금 계좌 | 카카오뱅크 3333-00-0000000 홍길동 |
| `PRICE_<상품키>` | 상품 가격(원). 상품키: counsel·love·pet·reunion·match·career·full·newyear·life | `PRICE_NEWYEAR=12900` |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` | 메일 발송. Gmail은 smtp.gmail.com / 587 / 주소 / **앱 비밀번호** | |
- 사장님 계정 만들기: `/app#/signup` 에서 `ADMIN_EMAIL` 주소로 가입 (다른 주소는 가입 거절됨)

## 순서
1. 새 신청 알림 메일이 오면 `/admin` → 신청 목록에서 '입금 대기' 확인
2. 통장에서 입금 확인 → 신청 열고 **입금 확인**
3. **풀이 만들기** → 상품 목차의 장마다 AI가 따로 씀 (2~13회, 1~3분). 화면을 닫아도 계속 진행
   - AI 순서: 코덱스(사장님 챗GPT 구독, 추가 비용 0 · 맥북에서만) → 제미나이(장당 몇 원). `saju/.env`의 `AI_PROVIDERS`
   → 다 되면 왼쪽에서 고치면 오른쪽에 바로 보임 → **저장**
   - 계산값보다 과장된 표현('과다', '없다')이 있으면 '사주 계산 결과 보기'와 대조해서 고친다
4. **PDF 미리보기**로 모양 확인
5. **손님에게 보내기** → 상태가 '발송 완료'로 바뀜
- 카톡·DM으로 온 손님: 목록의 **+ 손님 직접 입력** (바로 '입금 확인' 상태로 들어감)

## 상품 추가·변경
- 상품·가격·목차는 `saju/products.py` 한 곳. 새 운세는 한 덩어리 추가하면 신청서·관리 화면·PDF가 자동으로 따라감
- 손님에게 보이는 'PDF 약 N쪽'은 장 분량으로 자동 계산 (A4 한 쪽 ≈ 1,500자) — 과장 표시 방지

## 결과물
손님 메일함에 `운결_이름_상품.pdf` 첨부 메일. 관리 화면에 발송 시각 기록.

## 문제가 생겼을 때
- 관리 화면 경고 "메일 설정이 없어요" → `SMTP_*` 설정 전에는 메일이 실제로 안 나가고 서버 기록에만 남음
- Gmail 발송 실패 → 일반 비밀번호가 아니라 **앱 비밀번호**(구글 계정 → 보안 → 2단계 인증 → 앱 비밀번호)를 써야 함
- PDF에 □(빈 네모)가 보임 → 나눔 글꼴에 없는 글자(한자·특수 이모지). 풀이에서 그 글자를 빼고 저장. 표지는 이미 한자 없이 한글로 표시함
- "이미 작성된 풀이가 있습니다" → 다시 만들면 고친 내용이 사라지므로 확인 창에서 한 번 더 누를 때만 덮어씀
- 같은 사람이 한 시간에 신청을 10번 넘게 하면 1시간 차단 (스팸 방지)
